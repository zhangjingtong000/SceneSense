设计 5/5：端到端数据流与验收

第一阶段目标：从视频输入到 UI 展示，都能围绕稳定 Person 实体连续解释。

Pipeline after optimization
0. Detection
YOLO + tuned params
1. Tracking
track segments + quality
2. EntityProfile
track → Person mapping
3. KG
Entity/Event edges
4. UI
lifeline + evidence

Runtime flow

每帧检测和跟踪后，EntityProfile 更新 track→Person 映射。每 60 帧仍构建 SpatioTemporalEvent，但同时带着映射写 KG：Person 节点、Event 节点、belongs_to、next、累计 interacts_with。WebSocket 推送除了原 event，还推 entities、lifelines、kg_subgraph 的轻量数据。

验收标准

A

连续性

同一人遮挡后重现时，UI 主显示仍为同一个 Person，断点用虚线，原始 track IDs 可查。

B

时间轴对齐

事件热力和生命线严格按 frame scale 对齐，跳转到任意 Event 不漂移。

C

KG 证据可追溯

点击 Person 能看到 1-2 跳证据子图，边上有帧范围、置信度、来源 Agent、原始 track 证据。

D

性能不退化

KG 节点只存轨迹统计摘要，完整轨迹留在 EntityProfile；GraphML 保存不因轨迹点膨胀明显变慢。

实施顺序

Layer 0 和 Layer 1 并行；Layer 2 依赖 EntityProfile；Layer 3/4 依赖 KG 的实体/事件/边数据。每层都先做最小闭环，再加细节。
