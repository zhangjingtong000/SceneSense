设计 4/5：检测与跟踪优化边界

第一阶段不换 tracker，不上高级 ReID。目标是减少小人物漏检、遮挡断 ID 对连续理解的破坏。

0

Tracker 参数层

统一 web/CLI 参数入口：conf, imgsz, track_activation_threshold, new_track_thresh, lost_track_buffer, ReID/GMC 开关。默认针对人群小目标提高 imgsz、适当降低检测阈值、延长 lost buffer。

1

Entity 融合门控

遮挡后新 track 出现时，按 frame gap、预测位置、bbox 尺寸、方向、已有 ResNet18 appearance feature 做保守评分。高置信自动并入同一 Person，低置信只记录候选。

2

质量标注

每个 Person/segment 记录 tracking_quality: stable / occluded / fragmented / tentative。Agent 和 UI 都能看到"数据质量"，避免把检测断裂误判成行为异常。

明确不做

不替换成完整 BoT-SORT/Deep-OC-SORT，不训练新 ReID，不做多摄像头身份重识别。现有 tracker 的输出保持兼容，EntityProfile 在它上面吸收断裂。

验证

用 MOT17/现有上传样本验证：ID switch 数量、fragmented Person 数、平均 track segment 数、生命线缺口是否被正确标注。UI 上必须能看出"遮挡后重新接上"的虚线。
